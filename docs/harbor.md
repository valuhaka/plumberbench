# Running in Harbor

Needs a running Docker engine with `docker compose` (on a Mac: Docker Desktop, OrbStack or Colima), Harbor 0.26 (`uv tool install harbor`) and a key for the model's provider in the environment (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, ...).

## From GitHub

The 100 task folders are committed under `harbor/tasks/`, and `registry.json` names five datasets in them:

| Dataset | Tasks |
|---|---|
| `plumberbench-hard` | the ten level 5 houses, pictures only: start here |
| `plumberbench` | all 100: levels 1–5, seeds 0–9, both modes |
| `plumberbench-vision`, `plumberbench-facts` | the 50 of each mode |
| `plumberbench-smoke` | checks that pictures reach the model |

```bash
harbor run --repo valuhaka/plumberbench -d plumberbench-smoke -a opencode -m anthropic/MODEL --ak disable_web_search=true
harbor run --repo valuhaka/plumberbench -d plumberbench-hard -a opencode -m anthropic/MODEL --ak disable_web_search=true
harbor run --repo valuhaka/plumberbench -d plumberbench-vision -i l3-s007-vision -a oracle
```

`-i NAME` runs one task, `-l N` the first N. Pin a commit for reproducible runs: `--repo valuhaka/plumberbench@<sha>`.

## Private houses

The 100 committed houses are public, so a future model may have seen them, and an agent with a shell and internet access could fetch this repo and rebuild its house from the seed. For grading, generate houses nobody has seen:

```bash
uv run -m plumberbench.tasks --out private-tasks --random 10 --levels 5 --mode vision
harbor run -p private-tasks -a opencode -m anthropic/MODEL --ak disable_web_search=true
```

`--random 10` makes ten houses per level from 64-bit random seeds. The tasks are numbered (`l3-p00-vision`), not named after their seeds, since container names come from task names; the seeds are listed in `private-tasks/seeds.json` and otherwise appear only where the agent's container cannot see them. Harbor can also restrict the agent's container to named hosts (`network_mode = "allowlist"` under `[environment]` in `task.toml`), once you know which model API it must reach.

## The smoke test

Run it first, with the agent and model you will be judged with. `plumberbench-smoke` shows a new six-digit number in a picture on each of five calls and asks for the fifth. Its verifier reports PASS, STALE (an earlier picture: OpenCode issue #51652) or BLIND (pictures are not reaching the model).

## From a clone

```bash
harbor lint harbor/tasks/* harbor/smoke-vision
harbor run -p harbor/tasks/l3-s007-facts -a oracle
./scripts/judge_runs.sh anthropic/MODEL
```

`judge_runs.sh` checks the committed tasks are current, lints them, runs the smoke test (stopping if it fails), then on one task the reference solver (`oracle`), the do-nothing agent (`nop`), the stop-early and close-the-main baselines (`pb_agents.baselines`), and three agent runs. `OPENCODE_VERSION=x.y.z` pins OpenCode; `AGENT=codex` runs Codex instead (Harbor's Codex agent supports MCP servers and passes their pictures on).

## How a task is built

Each task runs the simulator in a sidecar container (`mcp-server`) and connects it to the agent over MCP. The episode log comes back as an artifact, and a separate verifier image replays it. The folders are generated by `uv run -m plumberbench.tasks` (which also writes `registry.json`); after changing the simulator, regenerate and commit. A test fails while the committed folders are out of date.
